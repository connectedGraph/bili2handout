# 写作风格指南

讲义的目标读者是**已经对这个主题有切身体会、正在寻找一套解释框架的人**。
写作不是向小白科普，而是帮他们把模糊的感受语言化、把散落的经验组织成体系。

## 语气

- 用「你」直接称呼读者，像一个想明白了的朋友在复盘，不像老师在上课。
- 先给判断，再给论证。每节开头尽量放一个反直觉结论或一个戳中人的场景。
- 允许口语词（「说白了」「要命的是」「你会发现」），但句子要完整、
  逻辑要干净——是整理过的口语，不是字幕搬运。
- 不端着，不煽情，不堆排比。可以有安慰，但安慰必须长在分析之后。

## 观点处理

- **博主的原生概念（黑话）是讲义最大的资产，一律保留原词**，
  首次出现时用 `\term{}` 标出并就地解释。不要把「椭圆」改写成「无意识念头」
  就完事——前者是社群暗号，后者是普通话，两个都要。
- 关键论断后标注出处，如（BV13HoGYiEgF）。讲义的可信度来自可溯源。
- 整理者的延伸推理要能看出是推论（顺着这个逻辑…… / 这意味着……），
  不能伪装成博主原话。好的讲义 = 七分提炼重组 + 三分诚实延伸。
- 博主说「这是我的猜测」的地方，保留这份不确定。
  用「原视频的猜想是」而不是「科学证明」。

## 结构节奏

- 一节只回答一个问题，节标题尽量是读者自己会问的那句话
  （「为什么学校会惩罚这种大脑」而不是「教育环境分析」）。
- 论证链：场景/判断 → 博主的模型解释 → 例子或类比 → 对读者的含义 →
  交给下一节。
- 每 1~2 页给读者一个「抓手」：洞察框、清单、表格或 `\key{}` 金句。
  纯文字墙对这类读者（以及这类主题对应的注意力状态）不友好。
- 类比优先用博主本人的（GPU/CPU、燃料、账本……）；自造类比要朴素，
  一个类比讲透就换，不要叠床架屋。

## 禁忌

- 不写成临床/学术/官方建议腔，不引用没在素材里出现的第三方研究。
- 不使用 emoji，不卖萌，不用「家人们」式直播腔。
- 不搞数字伪精确（「研究表明 87% 的人……」），素材里没有的数字不造。
- 不把方法写成保证：用「对有些人有效」「值得一试」，不用「一定能」。
- 不羞辱读者，也不把读者写成受害者；基调是「搞懂机制，然后工程化解决」。

## 自检三问（每章交稿前）

1. 把这一章里所有 \term 去掉，它还剩下博主独有的东西吗？没有 = 写成了通用废话。
2. 一个没看过视频的读者，能复述出这章的主判断和一个例子吗？
3. 这章结尾的问题，是不是下一章开头要接的？接不上 = 架构需要调。
